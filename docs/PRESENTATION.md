# MyIoT — презентация

## 1. MyIoT
Модульная IoT-система из отдельных кубиков. В текущей разработке — Main и Load.

## 2. Зачем нужны кубики
- **Main** хранит прошивку, исполняет локальную логику и связывается с сервером/интеграциями.
- **Load** выполняет команды двух каналов низковольтной DC-нагрузки.
- **Sensors** передаёт Main показания среды — будущий модуль.
- **Battery** обеспечивает автономное питание — будущий модуль.

Все модули подключаются к Main. Main один не включает полезную нагрузку.

## 3. Два кубика, с которых начинается система
**Main → Load → совместимая DC-нагрузка.**

Main принимает локальную команду, расписание или данные датчика в будущей версии. Он управляет выходами Load; нагрузочный ток не должен идти через GPIO. Main + Sensors + Load в перспективе позволяют связать измерение и действие.

## 4. Main Cube
- ESP32-C3 SuperMini — вычисления и Wi-Fi.
- USB-C — питание/подключение согласно конкретной ревизии платы.
- Внешняя кнопка 12 мм — механический элемент корпуса.
- Разъёмы предназначены для соединения модулей; окончательные pinout и маркировка требуют фиксации.

## 5. Load Cube
- Два N-канальных MOSFET-канала на AOD4184 в текущей схеме.
- На рендере видны два винтовых выходных клеммника и индикация каналов.
- Это не реле и не гальванически изолированный модуль.
- Рабочее напряжение и допустимый ток пока не подтверждены измерениями.

## 6. Ограничения
- Логические сигналы ESP32-C3 — 3,3 В; на GPIO нельзя подавать 5 В или нагрузочный ток.
- Load — только для последующих контролируемых низковольтных DC-испытаний.
- Не считать предельные параметры AOD4184 пределом всей платы.
- Сеть 230 В AC запрещена.
- Внешний модуль IRF520N — отдельная плата; его пользовательский тест не подтверждает характеристики Load Cube.

## 7. Что уже есть и чего пока нет
- Есть схемы Main и Load, CAD-модели PCB/корпусов и рендеры.
- Рендеры показывают концепт, а не физически собранное или сертифицированное изделие.
- Нет измеренного рейтинга Load, финального протокола модулей, Sensors/Battery и готового onboarding.

## 8. Бизнес-гипотеза и следующий шаг
Начать с DIY-аудитории и понятного набора Main + Load. Проверить безопасную работу каналов, собрать корпуса, реализовать кнопку/расписание, а затем провести интервью и ценовой тест. Цены, расходы и маржа в бизнес-плане — прозрачные сценарные допущения, не котировки и не продажи.

## 9. Вердикт
**Пока не готово к серии или инвестициям на масштабирование.** Следующий рубеж — стендовые измерения Load, рабочая демонстрация Main + Load, наблюдаемые тесты сборки и проверка готовности платить.
